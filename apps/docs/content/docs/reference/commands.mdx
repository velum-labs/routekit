# Commands

## Setup

```sh
routekit setup [--no-browser]
routekit config init [--provider <provider>] [--default-model <provider/model>]
routekit config init --empty
```

`setup` is the interactive multi-route onboarding flow. It does not accept
`--json` or `--no-input`. `config init` is the deterministic automation
primitive; no flags retain the OpenAI starter.

## Lifecycle

```sh
routekit start
routekit status
routekit stop
```

## Accounts and providers

```sh
routekit accounts login claude-code --name personal
routekit accounts login codex --name work
routekit accounts rename codex work personal
routekit accounts status
routekit providers add openai
routekit models list
```

## Remote gateways

```sh
routekit remote add <name> --url <gateway> --ssh <host>
routekit remote install <name>
routekit remote list
routekit remote show <name>
routekit remote use <name>
routekit remote remove <name>
```

Target overrides: `--remote <name>` and `--local`.

## Coding tools

```sh
routekit codex [provider/model] [--effort <id>]
routekit claude [provider/model] [--effort <id>]
```

`--effort` selects a provider-discovered opaque effort id for the chosen model.
Unsupported values fail before the tool starts. Claude Code uses its native
effort selector. RouteKit passes native `--effort <level>` instead of creating
synthetic model names. The exact supported builds are Codex CLI `0.146.0` and
Claude Code `2.1.216` or `2.1.220`; see
[client compatibility](/docs/reference/client-compatibility).

New tool surfaces should consume the shared contracts helpers
(`enumerateModelEffortVariants` / `resolveModelEffortVariant`) and either apply
the selection or reject it explicitly.

Codex uses the Responses API only. For an implicit launch, RouteKit selects only
advertised models with text output, tool support, and a compatible Responses
route. Selection is deterministic and does not cross from a subscription route
to a metered API route. A compatible configured default remains authoritative.
Otherwise, RouteKit first stays on the configured provider and uses its
advertised preference rank when available, then its model creation timestamps.
Only when that provider has no compatible model does selection widen to the same
billing class. Models without either signal are ordered by canonical ID only
when no ranked candidate is available. RouteKit does not infer age or quality
from model names, pricing, context size, or provider catalog order. An exact
model argument remains exact.

Direct OpenAI model discovery does not publish operation capabilities. When an
implicit Codex launch needs to classify or rank those models, RouteKit fetches
OpenRouter's public generation, embedding, image, and video model metadata.
Provider-native OpenAI creation timestamps remain authoritative; OpenRouter
only fills missing data. RouteKit sends only `Accept: application/json`: no API
keys, RouteKit tokens, configured model IDs, or account data. Explicit model
selection and a compatible configured default never make this metadata request.
General RouteKit model discovery remains provider-native. Bedrock's discovery
does not advertise model release time, so Bedrock-only fallbacks use canonical
ID order when no provider ranking signal is available.

Native clients own their own history, resume, and deletion commands. To pass
native arguments through the optional launcher, put them after `--`, for example
`routekit codex -- resume <native-id>` or
`routekit claude -- --resume <native-id>`.

## Persistent native-client setup

```sh
routekit codex install
routekit claude install
```

Installs are additive: Codex receives one `routekit` profile without changing its
default model; start it with `codex --profile routekit`, then use the RouteKit-
backed model picker. Claude receives native `availableModels` entries derived
from the RouteKit catalog, so its normal `/model` picker lists RouteKit models
without synthetic aliases. Each install issues a dedicated gateway
token and prints it once. Store and export `ROUTEKIT_GATEWAY_TOKEN` for Codex or
`ANTHROPIC_AUTH_TOKEN` for Claude. Reinstalling the same target preserves the
token; use `--rotate-token` to replace it. `uninstall` removes the RouteKit-owned
configuration and revokes its tracked dedicated token.

## Usage and quotas

```sh
routekit usage
routekit usage --watch 10
routekit usage redeem --provider codex
routekit usage redeem --provider codex --label work --credit-id RateLimitResetCredit_… --yes
```

`usage redeem` interactively selects an eligible account and reset credit when
they are omitted. Non-input use requires `--yes`; without an explicit ID it
chooses the soonest-expiring detailed credit, or lets the provider choose when
only an aggregate count is available.

## Usage leaderboard

```sh
routekit leaderboard
routekit leaderboard --by model --sort requests
routekit leaderboard --window 24h --json
```

Ranks named principals (default), models, or providers over retained call
attribution. With durable rollups enabled, the command defaults to the longest
supported retained window (`7d` for retention of at least seven days, otherwise
`24h`). Without durable rollups it defaults to `live`. Historical windows
require `leaderboard.durable: true` in `router.yaml`.


## Product telemetry

```sh
routekit telemetry status
routekit telemetry on
routekit telemetry off
routekit telemetry category <usage|reliability|adoption> <on|off>
routekit telemetry schema
routekit telemetry reset
```

Telemetry is explicitly opt-in and `DO_NOT_TRACK=1` always wins. `schema` shows
the exact event/field inventory; `reset` rotates the anonymous install identity.
The daemon uses RouteKit's bundled PostHog project token by default. A non-empty
`ROUTEKIT_POSTHOG_KEY` overrides it.
See [Privacy](/docs/concepts/privacy).
