# Connect coding tools

Use this guide after RouteKit has at least one working route. Verify that first:

```sh
routekit status
routekit models list
```

## Choose an integration

<Tabs items={["Codex", "Claude Code", "Cursor"]}>
  <Tab value="Codex">
    Launch Codex with an explicit RouteKit model:

    ```sh
    routekit codex openai/gpt-5.5
    ```

    Native arguments belong after `--`:

    ```sh
    routekit codex openai/gpt-5.5 -- --full-auto
    ```
  </Tab>

  <Tab value="Claude Code">
    Launch Claude Code with an explicit RouteKit model:

    ```sh
    routekit claude anthropic/claude-sonnet-4-5
    ```

    Native arguments belong after `--`:

    ```sh
    routekit claude claude-code/claude-sonnet-4-5 -- --continue
    ```
  </Tab>

  <Tab value="Cursor">
    Print Cursor's gateway URL, token, and model value:

    ```sh
    routekit cursor openrouter/anthropic/claude-sonnet-4.5
    ```

    Enter the values in Cursor's **Override OpenAI Base URL** settings. RouteKit
    does not launch the editor or `cursor-agent`; Cursor connects from its own
    process.
  </Tab>
</Tabs>

Omit the model to use the configured default when the client supports it.
`--effort <id>` selects a discovered reasoning effort, and `--cwd <dir>` sets
the tool working directory.

## Use another gateway

The launch commands accept `--gateway-url`, `--auth-token` or
`--auth-token-env`, and `--cwd`. Authenticated non-loopback gateways must use
HTTPS. Before spawning Codex or Claude Code, RouteKit confirms that the native
binary is on `PATH`.

## Install persistent configuration

Use native-client installation when you want the client to retain a RouteKit
profile or model picker without launching it through `routekit` each time:

```sh
routekit codex install
routekit claude install
```

Codex gets one additive `routekit` profile. Start it with
`codex --profile routekit` and choose from the RouteKit-backed model picker.
Claude Code gets RouteKit-owned gateway settings and native `availableModels`
entries. Existing configuration, MCPs, skills, plugins, and history remain
owned by the native client.

Each install prints a dedicated token exactly once. Store
`ROUTEKIT_GATEWAY_TOKEN` for Codex or `ANTHROPIC_AUTH_TOKEN` for Claude in your
secret manager. Reinstalling the same target keeps its token; use
`--rotate-token` to replace it.

## Use externally managed credentials

Pass `--no-token` when another environment owns credential injection:

```sh
routekit codex install --no-token
routekit claude install --no-token
```

This writes only RouteKit-owned client configuration. It does not issue,
register, change, or revoke a gateway token. Supply the matching environment
variable separately. `--no-token` cannot be combined with `--rotate-token`.

## Remove the integration

```sh
routekit codex uninstall
routekit claude uninstall
```

Uninstall removes only RouteKit-owned settings and revokes the tracked
dedicated token. Cursor has no install or uninstall subcommand.

## Verify and continue

Open the client's model picker or send a small prompt, then inspect the returned
`x-routekit-model-call-id` with `routekit calls inspect <call-id>`.
