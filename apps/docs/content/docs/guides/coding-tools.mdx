Use this guide after RouteKit has at least one working route. Verify that first:

```sh
routekit status
```

Run `routekit models list` only when you want to inspect the full catalog or
copy an exact model ID.

<Callout type="warn" title="Use a qualified client build">
  The supported builds are Codex CLI `0.146.0` and Claude Code `2.1.216` or
  `2.1.220`. Other versions are unqualified, not necessarily incompatible, and
  RouteKit does not reject them at runtime. See
  [supported coding tool versions](/docs/reference/client-compatibility) for evidence and
  the requalification policy.
</Callout>

## Launch from a project

<Tabs items={["Codex", "Claude Code"]}>
  <Tab value="Codex">
    ```sh
    cd ~/code/my-project
    routekit codex
    ```

    RouteKit selects a compatible startup model and loads the compatible
    RouteKit catalog into Codex's native model picker.

    Native arguments belong after `--`:

    ```sh
    routekit codex -- --full-auto
    ```
  </Tab>

  <Tab value="Claude Code">
    ```sh
    cd ~/code/my-project
    routekit claude
    ```

    RouteKit starts Claude Code with the configured model. The gateway exposes
    the RouteKit catalog to Claude Code's native model picker so you can switch
    routes during the session.

    Native arguments belong after `--`:

    ```sh
    routekit claude -- --continue
    ```
  </Tab>

</Tabs>

The launcher uses your current directory unless you pass `--cwd <dir>`. Open
the client's native model picker whenever you want to change models; where
supported, `/model` opens that picker.

To force the startup model for one session, put its exact namespaced ID before
`--`:

```sh
routekit codex openai/gpt-5.5
routekit claude claude-code/claude-sonnet-4-6
```

Use this form for automation, reproducible runs, and one-off model comparisons.
`routekit models list` shows the available IDs. `--effort <id>` selects a
discovered reasoning effort for the startup model.

## Connect to another RouteKit gateway

The launch commands accept `--gateway-url`, `--auth-token` or
`--auth-token-env`, and `--cwd`. Authenticated non-loopback gateways must use
HTTPS. Before spawning Codex or Claude Code, RouteKit confirms that the native
binary is on `PATH`.

## Install persistent configuration

Use native-client installation when you want the client to retain a RouteKit
profile or model picker without launching it through `routekit` each time:

```sh
routekit codex install
routekit claude install
```

Codex gets one additive `routekit` profile. Start it with
`codex --profile routekit` and choose from the RouteKit-backed model picker.
Claude Code gets RouteKit-owned gateway settings and native `availableModels`
entries. Existing configuration, MCPs, skills, plugins, and history remain
owned by the native client.

Both installs also add the product-owned `routekit` skill. It gives the coding
agent one workflow for RouteKit onboarding, configuration, recovery, and
compositional eval routing. Reinstall updates an unchanged RouteKit-managed
copy. RouteKit refuses to overwrite a user-owned or edited skill with the same
name.

Each install issues a dedicated gateway token and stores it in macOS Keychain,
or in a private `0600` RouteKit secret file on other platforms. Codex and Claude
retrieve it on demand through their native credential helper settings, so
terminal, IDE, and GUI launches need no shell changes. Reinstalling the same
target keeps its token; use `--rotate-token` to replace it.

Claude's `--bare` mode intentionally ignores normal user settings, including
`apiKeyHelper`; use a normal launch or pass its settings file explicitly.

## Use externally managed credentials

Pass `--no-token` when another environment owns credential injection:

```sh
routekit codex install --no-token
routekit claude install --no-token
```

This writes only RouteKit-owned client configuration. It does not issue,
register, change, or revoke a gateway token. Supply `ROUTEKIT_GATEWAY_TOKEN`
for Codex or `ANTHROPIC_AUTH_TOKEN` for Claude in the client environment.
`--no-token` cannot be combined with `--rotate-token`.

For a configured integration that needs explicit shell exports, run:

```sh
routekit token shell --tool codex
routekit token shell --tool claude
```

## Remove the integration

```sh
routekit codex uninstall
routekit claude uninstall
```

Uninstall removes only RouteKit-owned settings and revokes the tracked
dedicated token.

## Verify the integration

Open the client's model picker or send a small prompt, then inspect the returned
`x-routekit-model-call-id` with `routekit calls inspect <call-id>`.
