## Product lifecycle

Most RouteKit work follows the same five-stage loop:

1. **Configure** a provider or enroll a subscription account.
2. **Verify** live discovery with `routekit providers status` and
   `routekit models list`.
3. **Connect** a coding tool or authenticated HTTP client.
4. **Observe** health, usage, and call attribution.
5. **Diagnose** with `routekit doctor` and daemon logs when a route stops
   behaving as expected.

Use the [command reference](/docs/reference/commands) when you already know the
task and only need exact syntax.

## Before shared or production use

- Read [routes and billing](/docs/reference/routes-and-billing) for the selected
  route's credential owner, egress, limits, and failover behavior.
- Read [privacy and stored data](/docs/concepts/privacy).
- Use an exact build listed in [client compatibility](/docs/reference/client-compatibility).
- Keep the default loopback bind unless an authenticated network boundary is
  intentional.
- Use named data-plane tokens instead of sharing the private owner token.
