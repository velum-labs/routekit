# Cursor Desktop 3.12.30 compatibility qualification

Issue: [ENG-667](https://linear.app/velum-labs/issue/ENG-667/pin-supported-client-versions)

Result: **Fail — not offered**

Cursor Desktop 3.12.30 rejected RouteKit's custom model names before making a
gateway request. This build is not part of RouteKit's supported-client
contract.

## Tested environment

- Qualification date: 2026-08-01
- RouteKit package: `@velum-labs/routekit` 0.17.4
- RouteKit source revision:
  `0e5f726c36f6572c3a563561bec63f191794db45`
- Runtime: Node.js 22.23.2 on macOS arm64
- Cursor Desktop: 3.12.30
- Cursor build: `63a2996a10d9e476b6c28e951dd7691d9c0cf480`
- Gateway and upstream: isolated loopback RouteKit state with a deterministic
  OpenAI-compatible mock; no real provider or subscription request was made

The checkout contained uncommitted support-contract scaffolding during the
walkthrough. The built gateway, Cursor adapter, and launcher behavior matched
the recorded source revision.

## Procedure

1. Started RouteKit on an isolated loopback port with one mock-backed
   `openai/mock-model` route.
2. Enabled Cursor's Override OpenAI Base URL setting and pointed it at the
   gateway's `/v1/cursor` endpoint.
3. Added the canonical model name printed by RouteKit:
   `routekit/openai/mock-model`.
4. Selected the model in Cursor's Agent model picker and attempted one Agent
   turn.
5. Repeated the selection with the retained legacy dashed spelling
   `openai-mock-model` to distinguish a namespace-format failure from an
   endpoint failure.
6. Monitored the isolated upstream request log for method, path, model,
   streaming, tool presence, reasoning fields, and request count.

## Observed result

- Cursor accepted both strings into its custom-model list and displayed them in
  the Agent model picker.
- On send, Cursor rejected each selection with `AI Model Not Found` and
  reported that the model name was not valid.
- Cursor made zero requests to the RouteKit gateway and zero requests reached
  the mock upstream.
- Streaming, tool behavior, reasoning degradation, failure propagation, and
  fallback could not be measured because validation failed before transport.
- The bounded request requirement was satisfied only as a zero-request
  observation; it is not a successful qualification.

RouteKit therefore cannot claim Cursor Desktop 3.12.30 support. A future Cursor
build may be reconsidered only after it accepts a collision-safe RouteKit model
name and completes the full custom-endpoint walkthrough.

## Restoration and sanitization

- Removed both temporary custom model entries.
- Disabled the OpenAI base-URL override and cleared the temporary base URL.
- Removed the ephemeral mock-only OpenAI key from Cursor's secret storage.
- Stopped the isolated RouteKit daemon and mock provider after evidence
  collection.
- No credential, token, account identifier, prompt, response, raw transcript,
  user path, or request body is retained in this evidence.
